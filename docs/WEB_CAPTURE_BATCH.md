# 网页摘录小批量导入（本地草稿）

基于 PR #23 的 1ad372d9e27253eecddf127f6d92b4ea420f3634。保留单份导入；新增独立批量入口，不改变服务器接口、权限、文件发布或索引规则。

- 每批最多 10 份 `.nas-capture.json`，单份最多 256 KiB，总计最多 1 MiB。数量超限以一条批次级摘要整批拒绝，完全不遍历文件列表；总量超限逐项显示整批拒绝，不静默截掉尾项。逐份读取、校验并完整显示纯文本预览，所有文件均有独立状态。
- 展示目标项目名称及 ID，用户可取消各份勾选。仅点击确认后串行调用已有受鉴权、CSRF、项目角色及上传库权限保护的单文件接口。不会抓取来源 URL，也不保存新凭据。
- 本地同字段内容（包括时间）重复仅发首份；服务端已有、成功、无效、失败分别展示。来源/时间仍为文件自述，并未验证真实性；URL 凭据、查询、片段仍拒绝，不静默去掉后导入。
- 失败后不自动重试，完成件不会因再点确认重发。用户可重新选择失败件进行一次新的预览/确认；网络失败可能已保存，先检查原项目。索引排队不等于索引完成。
- 关闭窗口、切换项目/离开项目视图、退出登录点击时或会话过期时，立即使本批失效，不再发送下一项。无法撤销已送达服务器的请求；原项目可能已保存，需查看原项目。旧请求响应不会修改新的批次界面或解锁新任务。
- 批次仅存在当前页面内存，不持久化。关闭会清空预览和结果。文件名、标题和正文均用 textContent/文本节点显示，不解释 HTML。

## 验证与范围

Node 状态控制器测试：混合有效/无效/重复、顺序请求、取消勾选、计数/字节限额、重复字段、重复确认、不重试完成件、关闭/项目切换/退出导致的在途失效、旧文件读取与旧请求完成不污染新批次。使用合成数据，无真实网页或用户资料。

未操作用户 Windows/Mac、剪辑软件、NAS；未推送部署。真实浏览器桌面/移动布局、文件选择器及扩展联动没有验证，本地自动测试不替代这些验收。批量入口不是一键浏览器直传，仍是先导出再选择文件确认的两步流程。

当前验证：11 项新增 Node 测试通过；应用 Python 全套 396 项通过；JS 语法、相关 shell 语法、diff 空白检查通过。首次全套暴露 CSS/JS asset 版本不一致，已统一版本（最新 v71） 并重新全套通过。Docker CLI 当前不可用，未执行 compose config（未更改 compose/backend）。

默认 `.github/workflows/ci.yml` 已有 Node 22，在现有前端检查步骤追加 `node --test tests/js/capture-batch.test.cjs`（只运行一次）及模块语法检查。未更改发布/容器工作流。本地同命令可复现。URL 校验与后台一致：非空查询/片段拒绝，裸 `?`/`#` 后无内容时后台允许，前端也保留；空凭据 authority 仍拒绝。服务端始终最终裁定。
